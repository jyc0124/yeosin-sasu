> 작성 2026-11-13 · 근거: `data/factsheet.md`(Fact ID), 금융위 원문 `data/official/text/`
> 원칙: **판정은 이 문서대로 코드가 내린다.** LLM은 질문을 아래 입력 항목으로 바꾸는 일만 한다.

## 0. 전체 구조

```
창구 질문 ──(Liner Router: 조건 추출)──▶ 입력 항목(Case)
                                          │
                       ┌──────────────────┼──────────────────┐
                       ▼                  ▼                  ▼
                 M1 8.13 전세        M2 4.1 만기연장       M0 정보형 질문
                       │                  │                  │
                       └────────▶ 판정 카드(Verdict) ◀────────┘
                                   · 판정 코드 1개
                                   · 근거 Fact ID 목록 (원문 인용)
                                   · 필요 서류 / 역질문 / 확인 사항
                                   · 판정 경로(trace): 어떤 단계에서 결정됐는지
```

- **판정은 위에서 아래로 진행하다 처음 결정되는 단계에서 끝난다.** 여러 판정을 합치지 않는다.
- 판정에 꼭 필요한 입력이 `unknown`이면 그 단계에서 **역질문**으로 끝난다. 역질문에는 **그 단계에 필요한 항목만** 담는다.
- 판정 경로의 모든 단계는 Fact ID를 남긴다. 화면의 "근거 원문"은 이 ID로 원문을 찾아 보여 준다.

### 판정 코드
| 코드 | 의미 | 창구 행동 |
|---|---|---|
| `허용` | 규제 대상이 아니거나, 예외가 확정돼 서류만 있으면 됨 | 서류 징구 후 진행 |
| `조건부` | 확인 항목을 충족하면 허용(기간 제한, 증빙 필요 등) | 확인 항목 체크 |
| `불허` | 원칙적 제한에 해당하고 예외 없음 | 고객 안내, 다른 예외 재확인 |
| `심사위` | 여신심사위 판단 사항. 지점이 확답할 수 없음 | 상정 서류 준비 |
| `내부지침` | 금융회사 내부 기준에 위임됨 | A은행 지침 조회 |
| `보류` | 원문 공백 또는 최신 정보 필요. 확정 불가 | 본점 질의서 생성, Liner 감시 |
| `역질문` | 판정에 필요한 정보 부족 | 역질문 목록 제시 |
| `안내` | (11/21 추가) 고객 건 판정이 아니라 정부 발표 자료로 **확인된 기준**을 알려 주는 답(정의·기준일·적용 범위 질문). 남은 쟁점이 있으면 함께 표시 | 확인된 기준으로 고객 안내, 쟁점은 본점 질의 |

### 공통 입력
| 항목 | 값 | 비고 |
|---|---|---|
| `asOf` | 날짜 | 판정 기준일. 기본 오늘. 테스트셋은 2026-11-13 |
| `kb` | `v1` \| `v2` | v1 = 보도자료·FAQ만, v2 = 8.28 행정지도 포함 |
| `module` | `M1` \| `M2` \| `M0` | 추출 단계에서 분류 |

> 모든 불리언·날짜 입력은 `unknown`을 허용한다. 추출기가 질문에 없는 값을 지어내면 안 된다.

## 1. 공통: 주택 수 산정

M1(전세)은 **부부합산**, M2(만기연장)는 **세대 기준**(개인·개인 임대사업자)으로 센다 — 규제별 범위는 §1-3.
각 주택은 아래 항목을 가진다.

| 항목 | 값 |
|---|---|
| `region` | `seoul` · `incheon` · `gyeonggi`(=수도권) / 그 밖의 시도명 |
| `sigungu` | 시군구명 (예: 강화군, 금정구) |

| `acquiredBy` | `purchase` · `inheritance` · `gift` · `auction` · `presale` · `unknown` |

| `regulated` | 규제지역 여부 `true`·`false`·`unknown` (비수도권만 의미 있음) |

### 1-2. ➏ 인구감소(관심)지역 판정 (F401-03➏, F020-01·02)
```
지역표: data/kb/regions.json — 판본 3개
  faq0401     4.1 FAQ 참고표 (인구감소 89, 관심 16 기재 — 경남 사천·통영 누락)   ← KB v1
  gazette2021 2021 행안부 지정 (89·18)                       ← KB v2, 기준일 ≤ '26.10.19
  gazette2026 행안부 고시 제2026-61호 재지정 (92·18)          ← KB v2, 기준일 ≥ '26.10.20
접경지역표(17)는 판본과 무관

1. sigungu가 인구감소지역도 관심지역도 아님           → 해당 없음
   (v1에서 고객이 해당 지역이라고 주장하면 "확인 필요" — 참고표 누락 가능성, G-08)
2. 수도권이면 "접경지역인 인구감소지역"만 인정
     2026 판본: 인천 강화군·옹진군, 경기 가평군·연천군·동두천시  → 아니면 해당 없음
3. 광역시면 "군"만 인정 (예: 대구 군위군)          → 구(區)는 해당 없음 (예: 부산 금정구)
4. 기준시가 한도: 비수도권 인구감소지역 9억, 그 외 4억
     (그 외 = 관심지역, 수도권 접경 인구감소지역)
5. baseValueAtAcq unknown                          → 역질문 "취득 시 기준시가"
6. 한도 이하 → 제외 / 초과 → 해당 없음
```
- **판정 기준일의 지정을 쓴다.** ➏은 지역 목록을 행안부 지정에 맡기므로, 4.1 FAQ 표가 아니라 판정 기준일(`asOf`)에 유효한 고시를 적용한다. 재지정으로 지위가 바뀐 지역은 이유 문장에 "('26.10.20 재지정으로 A → B)"를 붙인다.
- **'인구활력+지역'**(여건이 개선돼 분류만 바뀐 곳, 예: 전남 영광군·강원 강릉시)은 고시상 **기존 지정 유지**이므로 그대로 인구감소(관심)지역으로 본다.
- **인천 동구 → 제물포구**: 행정구역 개편 표기. 엔진은 "동구"로 입력해도 제물포구로 조회한다(수도권·광역시 구라 결과는 해당 없음).
- **동두천시**: 2021 지정에서는 관심지역이라 수도권 예외("접경지역인 인구감소지역")에 들지 않았으나, **10.20 재지정으로 인구감소지역이 되어 ➏ 대상**(4억 한도)이다. KB v1(4.1 표만 아는 상태)과 v2의 판정이 갈리는 지점이다.
- **포천시**: 여전히 관심지역 + 접경지역 → 원문 문구대로 해당 없음, "해석 확인 권고"를 붙인다. 금융위 FAQ에 두 지역을 직접 언급한 자료는 없다(deep research #1).

### 1-3. 규제별 주택 수 범위 (11/22, `data/kb/house_scopes.json` · `lib/rules/scope.ts`)
같은 고객이라도 규제마다 주택 수를 세는 범위가 다르다. 그래서 주택 수는 하나의 숫자가 아니라 **보유 목록(명의자 `owner`)에서 규제별로 계산**한다. 범위 표는 데이터(근거 Fact ID 포함)이고 코드는 계산만 한다.

| 규제 | 범위 | 산정 예외 8가지 | 근거 |
|---|---|---|---|
| 8.13 비거주 1주택자 제한 | 부부합산 | 적용 | F813-01·04 |
| 유주택자 전세대출 한도 2억원 | 본인 + 배우자 | 미적용(F401-15) | F828-09 |
| 1주택자 전세대출 DSR | 세대 기준 | 미적용(F401-15) | F828-11 (세대 범위 세부 G-13) |
| 4.1 만기연장 제한 | 세대 기준 | 적용 | F401-01·03 (세대 범위 세부 G-13) |
| 보증기관 내규 | 공식 근거 없음 | — | G-14 |

- `owner`: self·spouse·joint(부부 공동명의 1채)·household(같은 세대 가족)·separated(세대 분리 가족, 배우자 제외). 없으면 모듈 관례(M1 = 본인·배우자, M2 = 세대 구성원).
- `countClaims`: 질문이 범위를 붙여 말한 수('DSR상 세대 1주택', '부부합산 2주택')는 그 범위에만 쓴다. 이전에는 이런 말을 담을 칸이 없어 규칙 밖 사실 → 보류였다(v3: 5건).
- 세대 기준 주택 수가 1이 아니면 1주택자 전세대출 DSR 규정을 적용하지 않는다(조건에 이유 표시). 가족 명의 주택만 있고 본인·배우자 주택을 모르면 부부합산은 0이 아니라 '모름'.
- 범위에 따라 수가 달라지거나 범위 붙은 수가 있으면 카드 '확인된 기준'에 규제별 주택 수를 보여 준다(`withScopes`).
- 검증: `tests/scope.test.ts` — 무작위 가족 구성 3,000건(+4.1 2,000건)으로 범위의 성질(세대 ≥ 부부, 예외는 8.13·4.1만, 같은 세대 가족 추가는 세대 기준만 1 증가, 세대 분리 가족은 4.1에서 제외)을 검사한다.
- **세대 범위가 애매하면 두 해석으로 판단**(`decide`, 11/22): 같은 세대 가족(owner=household) 명의 주택이 있으면 '넣은 수'와 '뺀 수'를 모두 계산해 규제의 주택 수 요건(1주택자·다주택자) 결론이 같을 때만 확정하고, 다르면 G-13으로 보류한다(1주택자 DSR 초과도 확정 불허하지 않음, 4.1 다주택자 여부도 보류). 예: 부부 무주택 + 같은 세대 조모 3채 → 넣든 빼든 1주택자 아님 → 확정.
- `owner=other`(전 배우자·친척 등)는 어느 범위에도 넣지 않는다.

## 2. M1 — 8.13 비거주 1주택자 전세대출 제한

### 입력
| 항목 | 값 | 설명 |
|---|---|---|
| `action` | `new` · `renewal` | 신규 / 만기연장 |
| `increase` | bool | 연장 시 증액 여부 |
| `maturityDate` | 날짜 | 기존 전세대출 만기(연장일 때) |
| `applicationDate` | 날짜 | 신규 신청(예정)일 |
| `contractAndDepositBy1231` | bool | 12.31까지 임대차계약 체결 + 계약금 납부 |
| `bankIntakeBy1231` | bool | 12.31까지 금융회사 전산 접수 완료 |
| `houses[]` | §1 | 부부합산 보유 주택 |
| `leasedOut` | bool | 보유 주택을 임대 중 |
| `tenantIsFamily` | bool | 임차인이 본인·배우자의 직계존비속 |
| `everLived` | bool | 본인 **또는 배우자**가 그 주택에 실거주한 적 있음 |
| `livedEvidence` | `resident_register` · `move_in_only`(전입신고만 하고 실제로 안 삶) · `move_in_record_only`(살았다는데 증빙이 전입 기록뿐) · `unknown` | 실거주 증빙 종류 |
| `exception` | 아래 ①~⑤ 중 하나 / `none` / `unknown` | 예외 허용 사유 |
| `targetAsserted` | bool | 질문이 "비거주 1주택 해당자"라고 전제함 → S1~S4 생략 |
| `plannedRenewalDate` | 날짜 | 만기 전에 미리 연장하려는 날짜(조기 연장 질문) |

### 판정 순서
```
S0 exception=① 법적 의무로 실거주 예정 → 허용 (대상자 여부와 무관하게 결과가 같음, F813-07①)
   targetAsserted=true               → S5로 (대상자 확정)
S1 주택 수(부부합산, §1 제외 적용)
   - unknown                         → 역질문 [보유 주택 수·명의]
   - 0                               → 허용 "무주택: 비거주 규제 대상 아님. 보증비율 80/90% 유지" (F813-11)
   - 2 이상                          → 불허 "다주택자: 기존 전세보증 제한 대상" (F813-10)
S2 대상 주택 요건 (F813-01)
   - isApt=false                     → 허용 "APT 한정 규제" 
   - 수도권 아님 & regulated=unknown → 조건부(L) "현재 규제지역 지정 현황 확인 필요" (G-07)
   - 수도권 아님 & regulated=false   → 허용 (단 27.1.1부터 1주택자 보증비율 80%, F813-11)
S3 임대 요건
   - leasedOut=false                 → 허용
   - tenantIsFamily=true             → 허용 "가족 임대 제외" (F813-02)
S4 실거주 요건 (F813-01⑶, F813-03)
   - livedEvidence=move_in_only        → 실거주 아님(기준은 '하루라도 실거주', F813-03) → 비거주로 진행 (11/19 수정, 이전: 보류)
   - livedEvidence=move_in_record_only → 보류 "증빙으로 전입 기록만 인정하는지 기준 없음" (G-01, A은행 지침 제4조)
   - everLived=true                  → 허용 + 서류 [실거주 이력 증빙] (F813-03, F828-03)
   - everLived=unknown 또는 배우자 이력 미확인 → 역질문 [본인·배우자 실거주 이력]
   ※ 여기까지 통과 = "비거주 1주택자" 확정
S5 시행 시점 (F813-09, F828-01·02)
   공통: 만기일·신청일 모두 unknown → S6으로 (신규 규정 가정, 확인 항목 [만기일·신청일])
   [kb=v1] 시행일 27.1.1만 알고 경과조치는 모름
     - 만기일 또는 신청일 ≤ 26.12.31, 12.31까지 계약·접수 여부가 쟁점, 또는 조기 연장(plannedRenewalDate ≤ 26.12.31 < maturityDate)
```

### 판정 순서
```
T1 대출 용도 (F401-05, F401-16)
   - interim·relocation              → 허용 "중도금·이주비는 제한 대상 제외"
   - commercial & 세대 주택 수 unknown → 조건부 "상가 등 임대사업용이어도 차주가 다주택자면 대상 → 주택 수 확인"
T2 대상 차주 (F401-01, F401-17, F401-18)
   - borrowerType이 landlord:
       landlordMainBusiness=unknown  → 내부지침 "주된 영업 판단은 금융회사 내부 기준" (A은행 지침 §2)
       corporate & homsAvailable=false → 조건부 "자산보유내역서·세무자료로 다주택 아님 입증 + 확약. 거부 시 불허" (F401-17)
       → 임대사업자는 대상
   - individual: 세대 주택 수(§1 제외 적용)
       unknown                       → 역질문 [세대 기준 주택 수]
       ➑ similar 태그 존재           → 심사위
       ≤1 & 제외 주택 있음 & houseCountIsMinimum('다주택'만 앎)
                                     → 조건부 "나머지가 1채뿐이면 대상 아님" + 역질문 [세대 주택 수] (B11, 리뷰 반영 11/13)
       ≤1 또는 conditionalDisposal   → 허용 "다주택자 아님" (+ 제외 주택 증빙)
T3 담보 요건 (F401-02)
   - 담보가 수도권·규제지역 APT 아님 → 허용 "제한 대상 담보 아님"
T4 시행 시기 (F401-12, F828-07)
   - maturityDate ≤ 26.4.16          → 허용 "종전 규정"
   ※ 쟁점 없는 질문 규칙: 담보·만기·예외 정보가 모두 unknown이고 주택별 태그·용도 같은 쟁점도 없으면
     → 역질문 [담보 소재지·APT 여부, 세대 주택 수, 대출 종류, 만기일, 임차인·등록임대·법적의무 여부] (예: C04)
     쟁점이 하나라도 있으면 담보 = 제한 대상, 만기 = 4.17 이후로 가정하고 진행하며
     확인 항목에 [담보가 수도권·규제지역 APT인지, 약정서상 만기]를 붙인다 (예: A06, B10, B13)
   ※ 담보 소재지 미확인(11/24 현장 피드백): 이 가정으로 불허가 나와도 담보 소재지·APT 여부를 모르면
     판정은 역질문("고객 확인 필요")으로 두고, 결론 문장에 "수도권·규제지역 아파트이면: …"을 붙이며 전제(premise)를 함께 보인다.
     갈림길(branches.ts): APT 여부 모름 → [수도권 APT / APT 아님], APT인데 소재지만 모름 → [수도권·규제지역 / 수도권 밖 비규제지역].
     담보 소재지는 collateral → 담보 표시 주택(isCollateral) → 본인 명의로 나온 유일한 주택 순으로 찾는다.
     테스트셋 A05·A06·B10(질문에 소재지 없음)은 불허·역질문을 모두 정답으로 인정(testset accept).
T5 예외 사유별 연장 가능 종료일 계산 (모두 계산 후 가장 늦은 날짜, F401-14)
   ① 임차인 (F401-06)               → tenantEnd()  (§3-1)
   ② 등록임대 (F401-07)             → voluntaryCancelDate ?? mandatoryEnd (+ 종료 후 임차인 규칙)
   ③ 법적 의무 (F401-08)            → legalObligationEnd
   ④ 신뢰보호 (F401-09)             → notifiedBy0401 → 조건부 "통보 사실 증빙(4.1 이전)"
   ⑤ 공익 (F401-10)                 → publicInterest → 허용 + 서류 [법인등록증]
   ⑥ 기타 (F401-11)                 → 심사위
T6 결론
   - 예외 종료일 E가 있고 E > maturityDate:
       연장 한도 = min(E, maturityDate + 1년) (F401-13)
       E > maturityDate + 1년 → 조건부 "1년 연장 후 재심사"
       그 외 → 허용/조건부 "E까지" + 서류
   - E ≤ maturityDate (이미 지남) 또는 예외 없음 → 불허 + "다른 예외 확인"
   - 예외 입력이 모두 unknown → 불허(원칙) + 확인 항목 [임차인·등록임대·법적의무·통보 여부]
   - 판정 코드 구분: 연장 기간이 줄어드는 것이 계산되면(E < 만기+1년, 또는 1년 주기 상한, 자진말소 시점) **조건부**,
     만기를 몰라 기간 계산이 안 되면 **허용** + "E까지, 1년 주기 재심사" 안내
   - (11/19 추가) 만기는 아는데 임대차 종료일 E를 모르면 허용으로 넘기지 않고 **역질문**(E가 만기보다 늦어야 연장 가능).
     법적 의무(③)는 '지금 팔 수 없다'가 근거라 종전대로 허용 + 종료일 질문.
   - (11/19 추가) E와 만기 중 하나가 추정 날짜(월만 알려 15일로 채움)이고 둘이 같은 달이면 **역질문**(정확한 일자에 따라 결론이 갈림).
   - (11/19 추가) 비수도권 담보의 규제지역 지정 여부를 모르면(G-07) 확정 불허 대신 **조건부**(M1 S2와 같은 처리).
```

### 3-1. 임차인 종료일 tenantEnd() (F401-06, 401FAQ Ⅲ-6)
```
provisional=true                                   → 인정 안 함 (가계약 미인정)
contractValidAt0401=false                          → 인정 안 함
renewal=none                                       → originalEnd
renewal=implicit & renewalDate 모름               → 역질문 [묵시적 갱신 시점] (유예 해당으로 가정하지 않음, 11/19)
renewal=implicit & renewalDate ≤ 26.4.16           → renewedEnd   (4.2~4.16 묵시적 갱신 유예)
renewal≠none & renewalDate ≤ 4.1 & originalEnd > 4.1 → 역질문 [4.1 당시 유효 계약이 어느 것인지] (11/19)
renewal=claim    & originalEnd ≤ 26.7.31           → renewedEnd   (4개월 내 종료 계약의 갱신청구권)
renewal=agreed / 그 밖의 갱신                      → originalEnd  (갱신계약 종료일 아님)
renewal=unknown & 갱신 결과가 판정을 바꿈           → 역질문 [갱신청구권 행사인가, 합의 재계약인가]
```
- 4.1 이전에 이미 체결된 연장계약(묵시적 갱신 포함)·후속 임차인 신규계약은 `renewal=none`, `originalEnd`=그 계약의 종료일로 넣는다.

### 4-2. 기준 질문 Q — 근거 조회 + 원문 대조 검증 (11/21, 고정 주제 목록의 한계 보완)
고정 주제(M0)에 없는 해석형 질문용. **판정 코드는 코드가, 문장은 Router가, 검증은 코드가.**
1. 추출기: `module=Q`, `basis = { subQuestions(1~5), regs, concepts }` — 어휘는 `data/kb/tags.json`(규제 9 × 개념 11).
2. 코드(`lib/basis.selectEvidence`): 규제와 개념이 **모두** 겹치는 Fact·공백만 고른다(결정적). 근거 0개면 LLM 없이 `보류`.
3. Router: 고른 Fact만으로 하위 질문별 문장(각 문장에 Fact ID). 답할 수 없으면 `unanswered`.
4. 코드: 문장마다 `lib/explain/verify.checkSentence`(인용 Fact 안, 숫자·날짜 출처, 내용 겹침, 대조·회피 표현). **인용 Fact와 내용이 겹쳐야만** 통과(카드 문장 출처 통과 없음).
5. 코드: 모든 하위 질문에 통과 문장이 있으면 `안내`, 하나라도 없으면 `보류`(확인된 부분 + 본점 확인). 결론 문장 = 통과한 첫 문장. 고객 건 허용·불허는 내지 않는다.
- 범위 밖(OUT) 질문에 범위 안 요소가 섞이면 고정 주제 → 없으면 같은 근거 조회로 그 부분만 답한다.
- 평가 A/B: `LOANDESK_NO_Q=1`이면 Q 없이(이전 구조) 추출.

### 4-4. 규칙 밖 사실 — 원문 대조 후에만 보류 (11/22, `lib/extract/ground.ts` · `lib/rules/index.ts guard`)
v3 블라인드 채점에서 '원문과 어긋남' 21건 중 16건이 같은 구조였다: 1차 추출기가 "항목에 담을 수 없다"고 한 사실을 엔진이 믿고 "정부 발표 자료에 기준이 없다"며 보류했는데, 원문에는 기준이 있었다.
1. **원문 대조(2차 추출)**: 규칙 밖 사실이 있으면 코드가 그 사실의 규제×개념 태그로 관련 Fact를 고르고(규제마다 몫을 나눔, 결정적), Liner Router가 같은 스키마로 한 번 더 추출한다. 원문이 그 사실을 판정 항목으로 다루면 항목에 담고, 요건이 아니면 '판정과 무관', 기준이 있지만 담을 항목이 없으면 `sourceFacts`에 Fact ID를 적는다. ID는 준 근거 목록·판정 근거 자료에 있는 것만 인정. 실패하면 1차 결과로 판정(안전 방향). A/B: `LOANDESK_NO_GROUND=1`.
2. **판정 단계 도달 여부**: 규칙 밖 사실이 바꾼다는 단계(주택 수·규제 대상·예외·적용 시점 → 판정 과정 S/T 단계)에 판정이 가지 않고 결론이 났으면(예: 중도금대출이라 T1에서 허용) 그 사실은 결론을 바꿀 수 없다 → 보류하지 않고 참고로만 표시.
3. **보류 문구**: '정부 자료에 기준이 없다'고 단정하지 않는다. 관련 기준이 확인되면 "관련 기준(F…)은 있으나 규칙 엔진이 판정 항목으로 다루지 못함"(그 Fact를 근거로 붙임), 못 찾았을 때만 "판정 근거 자료에서 기준을 찾지 못함"(G-09).
4. **커버리지**: 모든 Fact는 엔진(lib/rules·지역표·범위표)이 쓰거나 `data/kb/coverage.json`에 '설명용'으로 이유와 함께 있어야 한다(`tests/ground.test.ts`). '근거는 있는데 엔진이 모르는' 사실이 조용히 생기지 않게.
5. 판정 근거 자료 보강: F828-13 '규제지역' 정의(투기지역·투기과열지구·조정대상지역, 행정지도 1-라-(1)), F020-01 재지정 고시 등록·시행일(10.19 등록, 10.20 시행).

### 4-5. 규제 합성·경과조치·담보 주택·조건 표시 (11/22)
- **규제는 독립**: 8.13 제한·한도 2억원·1주택자 DSR 중 하나라도 신청 그대로를 확정적으로 막으면 `불허`(`blockBy`). 8.13 쪽 결론·확인 항목은 '(참고)'로 남긴다. 연장+증액이 한도를 넘거나, 대상자·예외 없음이 확인된 증액 연장도 묻는 그대로는 `불허`(대안 '증액 없이 연장'은 조건).
- 같은 질문에 다른 규제(DSR 비율·2억 초과 금액)가 함께 나오면 8.13 결론에 '[8.13 비거주 1주택자 제한]'을 붙인다(`labelMain` — DSR의 1주택자는 보유 주택 소재지와 무관).
- **규제별 신규 신청 경과조치**(`oldRuleForNew`, 기준일은 `house_scopes.json`의 newCutoff): 신청·임대차계약+계약금(`leaseDepositDate`)·전산 접수(`intakeDate`) 중 하나라도 기준일 이전이면 종전. 8.13 신규도 '26.12.31까지면 대상 요건을 묻지 않는다. `policyLoan`(버팀목·협약)은 DSR 제외.
- **4.1 담보 주택 자체가 예외 주택**(상속·채권보전 경매·어린이집·미분양·인구감소지역 등): 주택 수와 관계없이 그 담보 대출은 제외(401본 2-(1)). 담보 정보는 `collateral` + 보유 목록에서 `isCollateral`로 표시한 주택을 합친다.
- **등록임대 의무임대기간 종료 후 기존 임차인**(`afterMandatory`, 401FAQ Ⅲ-9, F401-07 후단): 기준 시점 = 의무임대기간 종료일. 그날 유효한 계약 종료일까지, 예외로 의무임대기간 종료일로부터 4개월 이내 종료 계약의 갱신청구권·'26.4.16까지 묵시적 갱신은 갱신계약 종료일까지.
- **조건이 있는 허용**(`Card.oblige`): 의무·추후 검증이 붙은 결론은 그 조건을 결론 문장에 반드시 함께 쓴다(판정 코드는 테스트셋 정의를 따름 — A16 '허용 + 실거주 시점 종료').
- **기준 자체를 묻는 질문**(`asksCriteria`): 고객 건의 가능·해당 여부를 전혀 묻지 않고 기준·구분만 물을 때만 기준 답변(§4-2)을 주 카드로, 고객 건 판정은 함께 표시.

### 4-1. M1 확장 — 증액·대환·함께 적용되는 전세 규제 (11/21, 현장 질문 세트 v1)

### 6-2. 정책 감시(F2) 조항 대응
- Router가 뽑은 조항은 **인용문이 원문에 그대로 있을 때만** 통과한다(공백 무시, 12자 이상). 실패한 추출은 화면에 내보내지 않고 건수만 표시한다.
- 기존 Fact 대응은 **검증된 인용문만으로** 계산한다(AI 요약은 미검증이라 쓰지 않음). 문자 bigram Dice ≥ 0.25, 같은 대책(8.13/4.1)의 Fact 안에서만. 0.25는 11/13 실제 실행 18개 조항에서 오대응 없이 F828-01·02·03·04·07을 모두 잡은 값이다.
- 승인 조건: 원문 다운로드 해시가 저장본과 같고(재생 모드 제외) 새 Fact 대응 조항이 1개 이상. 해시가 다르면 분석을 멈춘다.

### 6-3. 고객 안내 문구 검증기 (`lib/explain/verify.ts`)
- Router가 쓴 안내 문장은 아래를 모두 통과해야 화면에 나온다. 탈락 문장은 내용 없이 건수만 표시한다.
  1. 인용 Fact는 카드가 쓴 것만. 인용 Fact와 어휘가 겹쳐야(≥0.12) 그 ID를 근거로 표시하고, 아니면 카드 문장(결론·서류·확인 질문)과 충분히 가까울 때(≥0.25)만 '판정 카드' 출처로 통과
  2. 숫자는 단위까지, 날짜는 (연)월일로 대조. 출처 = 인용 Fact·카드. 고객 질문에서는 날짜만 인정(비율·금액은 정책 근거에서만)
  3. 판정과 어긋난 단정: 보류·심사위·역질문·내부지침은 '…인지는/여부/확인 후 안내/심사를 거쳐야/달라질 수 있/확인해 드리겠습니다' 같은 유보 표현을 지운 뒤 '가능·인정·수 있·문제없·충족·됩니다·로 봅니다·걱정 마' 등이 남으면 탈락. 조건부는 '자동·무조건·(확인·심사·서류) 없이' 탈락. 불허는 대출·연장이 된다는 약속('연장 … 됩니다/해 드리/가능')이 부정·제한 표현 없이 나오면 탈락(예외: '예외 사유에 해당하면' 조건절)
  4. 결론 뒤집기: 근거에 없는 대조 구문('…이 아니라', '말고', '대신'), 카드 결론의 핵심어를 반대말로('종전 규정' 결론에 단서 없는 '신규 규정'), 카드 단서의 조건어를 '…해도/하셔도'로 뒤집기('단, 증액하면' → '증액하셔도')
  5. 규제 회피 표현(`lib/hq/guard.ts`): 조기·앞당긴·만기 전 연장, 명의 이전·분산, 계약일 조정, 나눠 받기, 그리고 동사와 무관하게 '시점·날짜·만기일·올해 안·옮기·넣 … ~면 … 종전 규정 적용/연장 심사' 문형('증액하지 않으시면 종전 규정'처럼 규정 그대로의 조건문은 해당 없음)
- **한계**: 어휘·숫자·표현 규칙 검사이며 의미를 이해하지 않는다. 그래서 실패 방향을 '좋은 문장을 버리는 쪽'으로 둔다(11/13 실행: 130문장 중 92.3% 통과, 탈락은 모두 버려도 되는 문장이었고 통과한 문장 중 판정과 어긋난 것은 찾지 못함). 판정 코드는 이 문장과 무관하게 규칙 엔진이 정한다.
- 코드 리뷰 2회에서 만든 우회 문장 38개 중 37개를 막는다. 남은 1개(질문 속 고객 날짜 '12/20'을 정책 기한처럼 쓰는 문장)는 알려진 한계다.
