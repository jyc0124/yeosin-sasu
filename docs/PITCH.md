# 심사 설명 정리 — 무엇이 좋은가, Liner는 무엇을 했나

2026-11-16 정리. 근거 수치: docs/EVAL.md(45문항 평가), data/compare/RESULT.md(ChatGPT 대조 10문항). 영상 대본·기획서의 바탕.

## 용어 주의

- **서비스 이름은 "여신 사수"**, 부제는 **"규정 막힐 때 바로 묻는 대출 규제 사수"**(2026-11-19 변경, 이전 이름 '여신 창구 코파일럿'). 지점에서 막히면 찾는 사람이 '사수'다. 설명할 때: **"좋은 사수는 아는 건 바로 알려 주고, 모르는 건 '이건 본점에 물어보자'고 합니다."** — 단정하지 않고 본점에 올리는 설계와 같은 말이다. 저장소·배포 주소(loandesk-copilot)는 그대로.
- 화면·영상·기획서에서는 **"KB" 대신 "판정 근거 자료 v1/v2"**라고 쓴다. KB(Knowledge Base)가 KB국민은행으로 읽힐 수 있다. v1 = 보도자료·FAQ만, v2 = 8.28 행정지도·10.20 재지정 반영.
- **"원문" 대신 "정부 발표 자료"**(금융위원회 보도자료·FAQ·행정지도)라고 쓴다. "원문"만으로는 무엇인지 알 수 없다. 내려받은 파일의 일치 검증은 "원본 해시 일치"라고 쓴다(2026-11-19).
- **정답률은 반올림해 한 가지로 쓴다**: 최신 정보가 필요한 질문 **33% → 100%**(6문항 중 2개 → 6개), 전체 **91% → 100%**(45문항 중 41개 → 45개). 두 숫자는 **같은 4문항(A19·A20·B02·C07)**의 효과를 분모만 달리 센 것이다. 화면(/eval·사용 안내)도 같은 표기다.

## 만든 이유와 Liner (11/24, 심사 때 가장 먼저 말할 것)

> "시중은행 지점 직원 커뮤니티에서 들은 고충에서 시작했습니다. 정부 대책은 계속 바뀌는데 세부 지침은 늦게 내려와, 직원들은 건마다 규정을 찾고 본점 회신을 기다리느라 퇴근이 늦어지고, 급한 고객 앞에서 제때 답하지 못하는 스트레스를 털어놓고 있었습니다. 이 문제의 답은 최신 공식 문서를 찾아 출처를 붙이되 틀리게 단정하지 않는 것이고, 그건 Liner가 가장 잘하는 일입니다. 그래서 처음부터 Liner의 강점이 가장 값진 곳, 출처와 최신성이 중요하고 오답 비용이 큰 금융 창구에 맞춰 만들었습니다. 직원은 근거 붙은 답을 바로 받고, Liner는 금융 업무 안에서 매일 쓰이고, 저는 기관별 구축·감시 구독으로 사업을 할 수 있습니다."

- 고충은 커뮤니티에서 들은 그대로만 말한다(스트레스·늦은 퇴근·고객 대기). 정량 근거가 없는 표현(예: 질환)은 쓰지 않는다.
- Liner 강점 ↔ 실측 대응표: `docs/PROPOSAL.md` §0 · 화면 `/story`·`/review` 「만든 이유」

## 현장 소요시간 (현직 지점 직원 1명, 전언)

- 규정 해석 질문 하나: 짧으면 **수 분~30분**, 간혹 **2~3일**.
- 오래 걸리는 경우: 공지된 지침만으로 답이 안 나와 **본점 확인**이 필요할 때(꽤 많음). 가장 오래 걸리는 건 본점이 다시 **외부기관(HUG, 국토부 등) 문의 게시판**에 글을 올려 답을 기다릴 때.
- 여신 사수의 대응: 본점 질의에 **외부기관 문의 단계**를 넣었다. 물을 곳(금융위·보증기관·국토부·행안부)과 물어도 소용없는 것(금융회사 자체 판단 사항)을 코드가 가르고, 고객 정보 없는 질의문을 만들고, 같은 쟁점의 중복 문의를 하나로 묶는다.
- 말하는 법: "1명 응답 기준"을 밝히고 평균처럼 쓰지 않는다. 메시지는 **"질문이 지점 → 본점 → 외부기관으로 한 단계 올라갈 때마다 며칠씩 늘어난다. 여신 사수는 정부 발표 자료로 답이 나오는 질문은 지점에서 끝내고, 올려야 하는 질문은 쟁점이 정리된 질의서로 한 번에 올리고, 받은 해석은 FAQ로 재사용한다."**

## 지점 직원의 일을 덜어 주는 에이전트 (2026-11-19 추가)

**한 줄: "지점 직원은 고객 질문을 적고, 서류를 받기만 하면 됩니다. 판정, 본점 질의서, 여신심사위 안건 등록과 일정은 에이전트가 처리합니다."**

창구 질문 하나가 끝나기까지 에이전트가 대신하는 일(모두 코드가 하고, 결과가 매번 같음):

| 단계 | 예전(지점 직원이 직접) | 여신 사수 |
|---|---|---|
| 판정 | 보도자료·FAQ·행정지도를 찾아 대조 | 규칙 엔진이 판정하고 정부 발표 자료 근거(Fact ID)를 붙임 |
| 본점 질의 | 고객 상황·조항·쟁점을 정리해 질의서 작성 | 판정 카드로 질의서 자동 작성, 직원은 의견만 덧붙임 |
| 판정이 미심쩍을 때 | 동료·전화로 확인 | 확정 판정에도 '본점에 재확인 요청'(같은 자동 질의서) |
| 외부기관 문의 | 본점이 물을 곳을 찾아 질의문 작성 | 물을 곳·물어도 소용없는 것을 코드가 가르고, 고객 정보 없는 질의문 생성, 중복 문의는 하나로 묶음 |
| 여신심사위 상정 | 지점이 서류를 받아 직접 상정, 개최일 확인 | 본점이 회신하며 상정 결정 → **지점은 서류 체크만** → 안건 등록·개최일(둘째·넷째 수요일, 마감 3영업일 전) 자동 계산 → 결과가 나오면 지점에 알림 |
| 진행 확인 | 본점에 전화로 확인 | 단계가 바뀔 때마다 알림이 가고, 단계마다 고객 안내 문구를 줌("결과를 약속하지 마세요" 포함) |
| 같은 질문이 다시 올 때 | 다시 질의 | 승인된 본점 해석이 같은 쟁점의 판정 카드에 자동으로 나옴 |

**말할 때 지킬 것**
- **"자동 상정"이라고 하지 않는다.** 상정 여부는 본점이 정하고 서류는 지점이 받는다. 정확한 표현은 **"상정 결정 이후의 안건 등록·일정·통보를 에이전트가 맡는다"**.
- 상정 절차·개최 주기는 **가상 A은행 지침**(제3조)이고 실제 은행 절차가 아니다.
- **시간이 얼마나 줄었는지는 재지 않았다.** "몇 % 단축"이라고 말하지 않는다. 말할 수 있는 건 "지점 직원이 하는 일이 질문 입력·의견 작성·서류 체크로 줄었다"는 구조뿐이다. 현장 소요시간은 위 '현장 소요시간'(1명 전언)만 인용한다.
- '에이전트'가 하는 일은 판정·서류 정리·일정 계산·알림이고, 모두 결정적 코드다. LLM(Liner Router)은 조건 추출과 근거 설명에만 쓴다(절대 원칙 1).
- 시연용 저장 방식이라 같은 브라우저 안의 지점·본점 창끼리만 실시간으로 연결된다.

**시연 순서(2분)**: 지점 창과 본점 창을 나란히 놓는다. ① 지점: '발령으로 못 산 집' 판정(심사위 상정) → 질의서 보내기 ② 본점: 빨간 알림 → 회신하며 상정 체크 ③ 지점: 초록 알림 → 서류 체크 → 개최일 자동 표시 ④ 본점: 결과 입력 → 지점에 '심사위 승인' 알림. 시작 전 본점 화면 '데모 데이터 지우기'.

## 되묻고, 답을 받아, 다시 판정한다 (11/23)

**한 줄: "모르는 사실을 짐작하지 않고 묻습니다. 고객 답을 칸에 넣으면 조건으로 읽어 다시 판정하고, 무엇이 바뀌어 결론이 달라졌는지 보여 줍니다."**

- 일반 LLM은 빠진 사실을 가정하고 답한다(ChatGPT 비교에서 부분 정답·오답의 주된 원인). 여신 사수는 **결론이 갈리는 사실만** 골라 묻는다(예: 갱신청구권 행사냐 합의 재계약이냐).
- 답 칸: 예/아니오·선택지·날짜·"미확인". 한 질문에 사실이 여럿이면 칸을 나눈다(담보 소재지 / 아파트 여부). 칸에 맞지 않으면 고객 말을 문장 그대로 적어도 된다.
- 다시 판정한 카드 위에 **"담보 주택 (없음) → 서울 양천구 · 아파트 아님 / 불가 → 가능"**처럼 바뀐 조건과 결론을 보여 준다. 직원은 무엇 때문에 결론이 바뀌었는지 고객에게 그대로 설명할 수 있다.
- 안전: 답하지 않은 조건이 결론을 바꿀 수 있으면 '가능'을 내지 않고 다시 묻는다.
- 점검 범위(사실 그대로 말할 것): 엔진이 묻는 질문 **58종 전부**의 칸 구조를 점검했고, 나눈 칸의 답이 조건으로 읽히는지 **실제 Liner 호출로 확인**했다(10칸 사례 포함). 이 과정에서 찾은 문제 3건을 고쳤고, 저장 평가 재판정으로 의도한 1건 외 판정 변화가 없음을 확인했다. 대화형 흐름 전체를 대량 평가한 것은 아니다.
- 시연: 홈 '세입자 재계약 기준 연장' → 고객 확인 필요 → 답 칸에서 '합의로 재계약', 예외 사유, 담보 지역 입력 → 바뀐 조건과 결론 표시.

## "유의미하게 좋다"고 말할 수 있는 범위

- **말하면 안 되는 것**: "통계적으로 유의하게 정확하다." 문항을 팀이 만들었고, 엔진·프롬프트 개발에 같은 문항을 썼고, ChatGPT 대조는 10문항 1회다.
- **말할 수 있는 것**: **틀리는 종류가 다르다.** ChatGPT가 틀린 세 군데는 창구에서 민원·사고로 이어지는 곳이다.
  1. 최신 행정지도를 몰랐다 — B02(증액 조건 누락), C07(경과조치 기준 누락)
  2. 정부 발표 자료에 없는 것을 단정했다 — C02(가계약 인정 여부)
  3. 지점이 답하면 안 되는 것에 "네"라고 했다 — C05(여신심사위 사항), C07·B01-a(조기 연장 등 회피 경로를 후속 질문으로 제안)
- 여신 사수는 이 세 가지를 **구조로** 막는다: 판정은 규칙 엔진(코드), 정부 발표 자료에 없으면 본점 문의, 심사위 상정·은행 지침 확인은 본점 질의로 넘김, 회피 방법 비안내.
- 주장은 "더 똑똑하다"가 아니라 **"틀리면 안 되는 곳에서 안 틀리게 설계했다"**.
- 보조 근거: 표현만 바꾼 문항 28개에서도 KB v2 100%.

## Liner API가 한 일 (정확한 범위)

Liner는 여섯 가지 일을 맡는다(11/22 갱신: 아래 표 4가지 + 현장 질문 근거 조사 + 빠른 반응). 판정 코드는 규칙 엔진(코드)이 정하고, 그 앞(조건 추출)과 뒤(고객 안내 문구), 판정 기준 갱신(정책 감시), 해석 쟁점 사전 조사를 Liner가 맡는다. **"Liner 기여 4문항"은 이 중 정책 감시 하나의 효과다.** 화면 /eval의 'Liner가 맡는 일 6가지'·'왜 Liner였나'와 같은 내용.

| 하는 일 | Liner API | 범위 | 측정된 결과 |
|---|---|---|---|
| 조건 추출 | Router | **모든 판정**(45문항 전부, 새 질문 포함) | 뽑은 조건으로 판정해 45/45, 표현만 바꾼 질문 28/28. 사람이 정답 조건을 넣었을 때(45/45)와 같음 = 추출 오류 0 |
| 고객 안내 문구 | Router | **모든 판정 카드**(45/45) | 11/22부터 LLM은 새 문장을 만들지 않고 판정 결론 45 + 검수된 정부 발표 자료 문장 91을 번호로만 고름(136문장, LLM이 지어낸 문장 0). 예전 방식(LLM이 문장 생성)은 130문장 중 120문장(92%)만 대조 통과 |
| 정책 감시 | Search API·MCP `search_legal` | 판정 기준 갱신 | **8.28 행정지도** 발견 → 결론이 바뀐 **4문항**(A19·A20·B02·C07). 최신 정보 필요 6문항 33% → 100%, 전체 45문항 91% → 100%(같은 4문항). 원본 해시 일치, 인용문 대조 18/18 |

- 조항 구조화(정책 감시에서 찾은 행정지도를 Fact 후보로 정리)도 Router.
- **Liner 덕이 아닌 것(말하지 않기)**:
  - 판정 정확도 자체는 규칙 엔진에서 나온다. "Liner LLM이 더 똑똑해서"가 아니다. 조건 추출 수치는 "Router가 조건을 틀리게 뽑아 판정을 망친 경우가 없었다"는 뜻이다.
  - 10.20 인구감소지역 재지정은 deep research로 처음 찾고 Liner Search로 확인했다. 이 문서로 결론이 바뀐 문항은 없다.
- 해석 쟁점 사전 조사가 하는 일과 하지 않는 일: 공식 출처를 모아 '새 공식 문서 후보'와 '근거 자료에 있는 문서'로 나눌 뿐, 결론을 내지 않는다. 새 문서 후보가 있으면 정책 감시처럼 원문 대조·승인을 거쳐 반영하고, 없으면 외부기관 문의로 넘긴다(질의문에 "Liner로 공식 출처 N건 확인, 기준 없음"을 함께 실음). 화면에서는 Search Agent 답변 문장을 쓰지 않는다. 근거: `data/liner_spike/interpret_1119/REPORT.md`, 본점 화면 '질의 처리'.
- 정확한 표현: **"Liner는 모든 판정에서 고객 말을 조건으로 바꾸고 고객 안내 문구를 씁니다. 정책 감시자로서 보도자료에 없던 행정지도를 찾아왔고, 정부 자료에 답이 없는 쟁점은 외부기관에 묻기 전에 먼저 조사합니다. 찾은 문서는 정부 발표 자료와 대조하고 사람이 승인한 뒤에만 판정에 들어갑니다."**

## Liner 어필 핵심 (11/22 비교 실험 기준, 근거 `data/compare/search_1122/RESULT.md`)

- **8.28 행정지도 한 건으로 정답이 된 문항: 모두 15개.** 같은 문서로 정답이 된 문항은 테스트 질문 4개 외에 다른 세트에서도 11개(외부 출제 6·표현 바꾼 3·새 상황 1·현장 1, 그중 3개는 v1이면 위험 오류) — 저장된 조건 추출에 근거 자료만 바꿔 다시 판정한 결과(11/23, Liner $0).

2. **고객 질문만으로 그 문서를 찾은 것은 Liner.** 최초 발견(11/13)은 Search Agent에 질문으로 물어 참조 목록에서, 11/22 고객 질문 S4에서도 Liner Search Agent만 찾음(ChatGPT 0/3, 일반 웹 검색 0/3).

4. **API라 매일 돌릴 수 있고, 싸다.** 정책 감시는 같은 검색을 API로 돌린다(지금은 버튼 실행, 정기 실행은 운영 전환 때 연결). 웹 검색 1,000회 Liner $1 vs Brave·Perplexity $5, Tavily 약 $8, OpenAI 웹 검색 도구 $10+토큰. 정책 감시 1회 약 $0.008, 판정 1건 $0.026, 최초 발견 실험 $0.13.

Liner 입장에선 고객 은행 하나가 매일 감시·판정 사용량이다.

- **"재현성은?"** — 같은 B01 질문에 ChatGPT는 회차마다 답이 달랐다(한 회차는 가족 임대 예외를 빠뜨림). 여신 사수는 추출된 조건이 같으면 판정이 항상 같다(조건 추출은 LLM이지만 45/45·28/28 추출 오류 0).
