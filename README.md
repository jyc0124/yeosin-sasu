# 여신 사수 — 규정 막힐 때 바로 묻는 대출 규제 사수

> 은행 지점 창구 직원을 위한 **대출 규제 판정 에이전트** · Liner .EXE-THON 출품작(장재영 1인 참가)
> 배포: https://loandesk-copilot-rosy.vercel.app/?view=judge (심사위원 설명을 켠 화면, 왼쪽 아래 스위치를 끄면 창구 직원 화면) · 기획서: [`docs/submission/여신사수_기획서.pdf`](docs/submission/여신사수_기획서.pdf)(제출용 2쪽, 상세판 [`docs/PROPOSAL.md`](docs/PROPOSAL.md)) · 영상 나레이션: [`docs/submission/VOICE_SCRIPT.md`](docs/submission/VOICE_SCRIPT.md)(장면 기획 초안은 [`docs/VIDEO.md`](docs/VIDEO.md))
> **심사위원께**: 위 배포 링크(`?view=judge`)로 열어 **왼쪽 아래 「심사위원 설명 보기」를 켠 채** 보시기를 권합니다. Liner가 쓰인 곳, 처리 시간, 근거 번호, 평가 수치가 화면마다 함께 보입니다. 끄면 창구 직원이 실제로 보는 화면입니다.
> 저장소·주소의 `loandesk-copilot`은 이전 이름(여신 창구 코파일럿)입니다.

**만든 이유**: 시중은행 지점 직원 커뮤니티에서 들은 고충에서 시작했습니다. 정부 대책은 계속 바뀌는데 세부 지침은 늦게 내려와, 직원들은 건마다 규정을 찾고 본점 회신을 기다리느라 퇴근이 늦어지고, 급한 고객 앞에서 제때 답하지 못하는 스트레스를 털어놓고 있었습니다. 이 문제의 답(최신 공식 문서를 찾아 출처를 붙이되 틀리게 단정하지 않기)은 **Liner가 가장 잘하는 일**(출처가 붙는 검색·여러 문서 조사·업무에 넣는 API)과 겹칩니다. 그래서 처음부터 Liner의 강점이 가장 값진 금융 창구에 맞춰 설계했고, 직원(근거 붙은 답을 바로)·Liner(금융 업무 안에서 매일 쓰이는 API)·만든 사람(기관별 구축·감시 구독) 모두에게 이득이 되게 했습니다. 자세히: [`docs/PROPOSAL.md` §0](docs/PROPOSAL.md).

**만든 사람**: 저는 은행원이 아닙니다. 컨설팅, AI 교육, AI로 제품·서비스를 만들어 사업화하는 일을 하며 여러 조직의 현장 고충을 듣고 AI로 풀어 왔습니다. 지점 직원 커뮤니티에서 같은 질문이 반복되는 것을 보고, 혼자 판단하지 않고 현직 직원에게 네 번 검증받으며 만들었습니다(설계 · 11.21 현장 질문 · 11.22 사용 검토 · 11.24 재확인).

고객 말을 그대로 입력하면 **정부 발표 자료(금융위원회 보도자료·FAQ·행정지도) 근거와 함께 판정 카드**를 돌려줍니다. 판정은 LLM이 아니라 **규칙 엔진(코드)**이 내리고, 정부 발표 자료에 답이 없으면 확답하지 않고 본점으로 올립니다.

다루는 정책:
- **2026.8.13** 「부동산 시장 안정을 위한 금융 종합대책」 — 비거주 1주택자 전세대출 제한
- **2026.4.1** 「'26년도 가계부채 관리방안」 — 다주택자 수도권·규제지역 아파트 주담대 만기연장 제한

> ⚠️ 정부 발표 자료와 **가상 사례**만 씁니다. 은행 지침은 **가상 A은행**(`data/bank/`) 기준이며 실제 은행 기준이 아닙니다. 판정은 참고용이고 최종 판단은 금융회사의 기준과 여신심사 절차를 따릅니다.

## 설계 원칙

1. **판정은 코드가 내린다.** `lib/rules`의 규칙 엔진만 판정 코드를 정한다. LLM은 조건 추출·안내 문장에만 쓴다.
2. **모든 근거는 Fact ID로 추적한다.** 근거는 `data/kb/facts.json`(원본 `data/factsheet.md`)에만 있다. 원문에 없으면 `보류`.
3. **LLM 문장은 정부 발표 자료와 대조한 뒤에만 화면에 낸다.** Search Agent 답변은 판정 경로에 쓰지 않는다.
4. **규제 회피 방법은 안내하지 않는다.**

## 현장 의견 반영

현직 직원들의 지점 업무 고충과 질문이 쏟아지는 **지점 직원 커뮤니티**의 내용을 바탕으로 만들었습니다. 그 커뮤니티에 속한 현직 지점 직원 한 명이 커뮤니티의 질문·의견을 전해 주고 직접 써 보며 검토했고, 지적을 받으면 고친 뒤 다시 확인받았습니다. 자세한 기록은 화면의 심사 안내 `/review#field`에 있습니다.

| 날짜 | 현장에서 받은 것 | 반영 |
|---|---|---|
| 설계 | 커뮤니티에서 반복되는 쟁점 유형 | 테스트 질문 45개 중 15개 |
| 11.21 | 현직자가 일반화한 현장 질문 14문항 | 범위 안 9개 중 정답 2 → 일반 규칙으로 고쳐 14문항 모두 직접 답함(직접 채점), 새 상황 질문 41/41 |
| 11.22 | 현직 직원 사용 검토(실제 질문 3건 + 사용 후기 + UI 수정안) | 같은 등본 가족 주택 합산이 커뮤니티 실제 답과 핵심 일치 |
| 11.23 | 검토 의견 16개를 항목별로 대조 | 반영 8 · 일부 반영 5 · 아직 못 함 3을 이유와 함께 직원에게 회신 |
| 11.24 | 고친 화면 재확인 | "사용성이 많이 좋아졌다" · 남은 지적 1건(담보 지역을 모르는데 '불가'가 먼저 보임) 당일 반영 |

현장이 말한 부족함(보증기관·은행별 기준)은 엔진이 아니라 공개되지 않은 자료에서 옵니다. 현직 직원들은 **"은행 내규·보증기관 자료가 들어가면 단계적으로 테스트하면서 실무에 사용해 볼 만하다"**고 했고, 은행 보안 문제도 함께 해결하며 진행해야 한다고 했습니다(11/24). 자료를 넣는 길은 이미 돌려 봤습니다: 정부 후속 문서 한 건을 넣자 엔진은 그대로인데 33% → 100%.

## Liner API를 사용한 기능

**고객 상황만으로 8.28 행정지도를 찾은 건 Liner였고, 그걸 API로 매일 돌릴 수 있습니다.** 창구는 문서 이름을 모르고 고객 상황만 압니다. 같은 창구 질문으로 Liner Search Agent는 행정지도를 찾았고(1/3) ChatGPT 웹 검색·일반 웹 검색은 못 찾았습니다(0/3 · 0/3, `data/compare/search_1122/RESULT.md`). 개발 첫날 이렇게 찾은 문서 한 건이 정답률 33% → 100%의 열쇠였습니다. 문서 이름을 알면 ChatGPT도 찾습니다. 차이는 처음 찾는 힘과, 그걸 API로 매일 자동 감시할 수 있다는 데(검색 1,000회 $1) 있습니다.

| 하는 일 | Liner API | 코드 | 측정 결과 |
|---|---|---|---|
| 고객 말 → 판정 조건 추출 | Router (`liner-gpt-router`, 대체 `liner-gemini-router`, `json_schema`) | `lib/extract` | 추출 조건으로 45/45, 표현 바꾼 질문 28/28 |
| 고객 안내 문구 | Router | `lib/explain` | LLM이 새 문장을 만들지 않고 판정 결론 45 + 검수된 정부 발표 자료 문장 91을 번호로만 고름(136문장, LLM이 지어낸 문장 0). 예전 생성 방식은 130문장 중 10문장이 대조에서 탈락 |
| 정책 감시 | Search API(`/tools/search/web`) · MCP `search_legal`, 조항 구조화는 Router | `lib/watch` | 보도자료·FAQ에 없던 **8.28 행정지도** 발견 → 최신 정보 필요 6문항 33% → 100% |
| 해석 쟁점 사전 조사 | Search API | `lib/research` | 쟁점 1건 2~3초, $0.002(실측) |
| 보증기관 공개 자료 연결 | Search API | `lib/guarantor`, `data/guarantor/` | Liner 검색(18회, $0.018)과 공식 사이트 직접 확인으로 HF 업무지침 등 공식 문서 8건 연결. 판정에는 쓰지 않고 원문만 연결 |
| 빠른 반응 | Router 스트리밍 | `lib/liner`, `app/api/judge` | 조건을 읽는 대로 표시, 첫 반응 약 2.6초 |

모든 호출은 `lib/liner`(재시도·캐시·직렬 큐·출처 신뢰도)를 거칩니다. 자세한 범위·비용은 [`docs/PITCH.md`](docs/PITCH.md) 'Liner API가 한 일'.

## 실행

Node.js 20 이상이 필요합니다.

```bash
npm install
cp .env.example .env      # 그다음 .env를 열어 LINER_API_KEY= 뒤에 심사용 키를 넣고 저장 (코드에는 키가 없습니다)
npm run liner:smoke       # Liner 연결 확인(Router·Search·MCP)
npm run dev               # http://localhost:3000
```

| 환경변수 | 필수 | 설명 |
|---|---|---|
| `LINER_API_KEY` | ✅ | Liner API 키 |
| `LOANDESK_DEMO_REPLAY=1` | | Liner를 부르지 않고 `data/demo_cache`의 저장 응답만 사용(영상 장면 재생) |
| `LOANDESK_DEMO_ASOF=2026-11-23` | | 기준일 고정. 재생 모드와 함께 켠다 |
| `NEXT_PUBLIC_BETA=0` | | 베타 테스트 전용 화면(판정별 피드백·의견 보내기)을 끈다 |
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` | | 베타 피드백 저장소(Upstash Redis). 없으면 서버 로그에만 남김 |

**심사용 실행에는 `LINER_API_KEY` 하나만 있으면 됩니다.** KV 값은 베타 테스트 때 직원 피드백을 모으던 저장소라, 없으면 피드백이 서버 로그에만 남고 나머지 기능은 그대로 동작합니다.

**키 없이 데모 장면만 보기**: `LOANDESK_DEMO_REPLAY=1 LOANDESK_DEMO_ASOF=2026-11-23 NEXT_PUBLIC_BETA=0 npm run dev` 후 [`docs/VIDEO.md`](docs/VIDEO.md)의 질문을 그대로 붙여 넣으세요. 저장된 응답만 쓰므로 Liner 키가 없어도 됩니다.

## 평가 재현

**대표 업무 흐름 3건의 실제 응답**: [`docs/EVIDENCE_CASES.md`](docs/EVIDENCE_CASES.md) — 되묻기 → 고객 답 → 다시 판정 / 근거 자료 v1 → v2(Liner가 찾은 8.28 행정지도) / 본점 이관. 질문·Liner가 읽은 조건·판정·근거 번호·판정 경로·처리 시간을 실시간 호출 그대로 남겼습니다(`node scripts/tools/evidence-cases.mjs`).

| 명령 | 내용 |
|---|---|
| `npm test` | 자동 테스트 523개(규칙 엔진·안전장치·질의·쟁점 대장 등, Liner 호출 없음) |
| `npm run eval:extract -- --no-cache` | 테스트 질문 45문항: 질문 → Liner 조건 추출 → 판정(v1·v2). 결과 45/45 |
| `npx tsx --env-file=.env scripts/eval-novel.ts --no-cache [--set=holdout\|holdout2]` | 처음 보는 질문 21 + 검증 10 + 10. 결과 41/41, 틀린 확답 0 |
| `npm run eval:report` | 비교표 생성(`docs/EVAL.md`, `/eval`). Liner 호출 없음 |
| `npm run data:build` | `data/factsheet.md`·`data/testset_v0.md` → JSON |

평가 문항은 직접 만들었습니다. 위 결과는 세트별로 최종 보고한 실행 1회의 값이고, 개선 과정에서 다시 잰 기록도 모두 남겼습니다. 새 상황 질문 41개 중 기본 21개는 첫 측정(16/21) 뒤 일반 규칙을 고쳤고, 검증용 20개는 고치기 전에 떼어 두었습니다. 실행 기록은 `data/eval/runs/`, ChatGPT 대조 원문은 `data/compare/`(11/16 일반 채팅, 11/22 웹 검색 켬 `search_1122/`).

## 기존 / 신규 구분

모든 코드와 데이터는 해커톤 기간(2026-11-13 첫 커밋 ~ 제출)에 새로 만들었습니다. 이 공개 저장소는 제출 시점의 파일을 한 커밋으로 올린 것이고, 개발 과정의 커밋 기록은 비공개 저장소에 있어 요청하시면 보여 드립니다. 가져다 쓴 것은 공개 라이브러리(Next.js, React, Tailwind CSS, Vitest, Pretendard 글꼴)와 공개 자료뿐입니다: 정부 발표 자료(금융위원회 보도자료·FAQ·행정지도·감독규정, `data/official/`), 보증기관(HF·HUG) 공개 문서 발췌·링크(`data/guarantor/`). 은행 지침은 직접 만든 가상 A은행 기준(`data/bank/`)이고, 현장 질문은 현직자가 개인정보·고객 사례 없이 일반 질문으로 다시 쓴 것입니다.
